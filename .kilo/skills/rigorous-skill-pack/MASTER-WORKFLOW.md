# MASTER-WORKFLOW — 端到端工程總控流程

**版本**: v1.0.0  
**適用**: AI 時代嚴謹軟體工程技能包，工作區層級  
**總控層**: `skills/00-orchestration/SKILL.md`

---

## 總覽

本流程定義 G0–G10 十個階段，從專案盤點、產品探索、需求規格、UX、架構、實作、測試、安全、發布到持續演進。每個階段皆有明確的品質閘門與停止條件。AI 代理人必須依序執行，且不可跳過品質閘門。

---

## G0 — 專案盤點與風險分級

**目標**: 盤點專案現況，確定風險分級，選擇適用技能。

**輸入**: 專案根目錄、既有 AGENTS.md、既有技能清單。

**輸出**: 風險分級（低/中/高）、適用技能清單、停止條件清單。

**品質閘門**:
- [ ] 確認專案是否為 git repo
- [ ] 確認既有 AGENTS.md 內容，不得覆蓋
- [ ] 風險分級已記錄

**停止條件**: 風險分級為「高」且缺乏安全技能支援時，停止並升級。

---

## G1 — 產品探索

**目標**: 確認使用者價值與需求假設，避免功能堆砌。

**技能**: `01-product-discovery`

**輸出**: 產品簡報（templates/）、價值假設清單、非目標清單。

**品質閘門**:
- [ ] 價值假設已記錄
- [ ] 來源授權已檢查（docs/source-registry.md）
- [ ] 非目標已明確列出

**停止條件**: 價值假設無法驗證時，停止並重新探索。

---

## G2 — 需求與領域建模

**目標**: 將需求轉成規格、領域模型與邊界。

**技能**: `02-requirements-specification`

**輸出**: PRD（templates/）、領域模型、追溯矩陣。

**品質閘門**:
- [ ] PRD 已完成並被審查
- [ ] 需求具有可追溯 ID
- [ ] 領域邊界已定義

**停止條件**: 需求歧義未消除時，停止並釐清。

---

## G3 — UX 與無障礙

**目標**: 確保介面可用且符合無障礙標準。

**技能**: `03-ux-and-accessibility`

**輸出**: UX 規劃、無障礙檢查表、原型（如適用）。

**品質閘門**:
- [ ] 無障礙檢查表已執行
- [ ] 鍵盤導航可用
- [ ] 色彩對比符合標準

**停止條件**: 無障礙檢查未通過時，停止並修正。

---

## G4 — 架構與 ADR

**目標**: 確定系統架構，記錄架構決策。

**技能**: `04-architecture-and-adr`

**輸出**: 架構圖、ADR（templates/）、元件關係圖。

**品質閘門**:
- [ ] ADR 已記錄決策與原因
- [ ] 架構符合工作區憲章不變量
- [ ] 零 JavaScript 展示層（若適用）

**停止條件**: 架構決策未經審查時，停止並審查。

---

## G5 — 任務規劃

**目標**: 將規格拆解為 DAG 工單，1 Ticket = 1 Context Window。

**技能**: `05-task-planning`

**輸出**: 任務清單、DAG 工單、依賴關係。

**品質閘門**:
- [ ] 每個工單有明確定義完成（DoD）
- [ ] 工單間依賴已標註
- [ ] 工單大小適合單一上下文視窗

**停止條件**: 工單過大或依賴環狀時，停止並重新拆解。

---

## G6 — TDD 與實作

**目標**: 先寫測試，再實作，保持 100% 測試通過與零警告。

**技能**: `06-tdd-and-implementation`

**輸出**: 程式碼、測試、實作記錄。

**品質閘門**:
- [ ] 測試先行（紅綠重構）
- [ ] `cargo clippy --all-targets -- -D warnings` 零警告（Rust 專案）
- [ ] `#![forbid(unsafe_code)]`（Rust 專案）

**停止條件**: 測試未通過或有警告時，停止並修正。

---

## G7 — 系統化除錯

**目標**: 對 Bug 優先使用系統化除錯流程，不盲目修改。

**技能**: `07-systematic-debugging`

**輸出**: 根因分析、除錯記錄、修正程式碼。

**品質閘門**:
- [ ] 根因已確認
- [ ] 修正有對應測試
- [ ] 回歸測試通過

**停止條件**: 根因不明時，停止並 escalate。

---

## G8 — 程式碼審查

**目標**: 行為與架構雙盲審查，附帶形式化回滾證明。

**技能**: `08-code-review`

**輸出**: 審查報告、回滾證明、PR/MR。

**品質閘門**:
- [ ] 行為審查通過
- [ ] 架構審查通過
- [ ] 回滾證明已記錄

**停止條件**: 審查未通過時，停止並修正。

---

## G9 — 品質測試與安全

**目標**: 執行品質測試、安全審查、威脅模型。

**技能**: `09-testing-and-quality`、`10-security-and-privacy`

**輸出**: 測試報告、威脅模型、安全審查結果。

**品質閘門**:
- [ ] 所有測試通過
- [ ] 威脅模型已完成
- [ ] 最小權限原則已驗證
- [ ] 無資料外洩風險

**停止條件**: 安全審查未通過時，停止並修正。

---

## G10 — CI/CD 與發布

**目標**: 建置、測試、部署、回滾、備份還原。

**技能**: `12-ci-cd-and-release`、`13-observability-and-reliability`、`14-retrospective-and-evolution`

**輸出**: 發布檢查表、部署記錄、回滾程序、備份還原記錄。

**品質閘門**:
- [ ] 發布檢查表已執行
- [ ] 回滾程序已驗證
- [ ] 備份還原已測試
- [ ] 可觀測性已啟用

**停止條件**: 部署回滾測試未通過時，停止發布。

---

## 持續演進

發布後進入 `14-retrospective-and-evolution`，記錄回顧、經驗教訓，並將改善項目納入下一週期的 G0。

---

## 風險分級與停止條件摘要

| 風險分級 | 說明 | 停止條件 |
|----------|------|----------|
| 低 | 內部工具、無敏感資料 | 一般錯誤即停止 |
| 中 | 有使用者資料、需授權 | 跨租戶資料外洩風險即停止 |
| 高 | 正式環境刪除、自動付款、安全相關 | 任何停止條件觸發即立即停止並升級 |

---

## AI 自稱完成 vs 實際證據

- 僅接受「實際證據證明完成」：檔案存在、命令退出碼為 0、測試通過、驗證腳本 PASS。
- 不接受僅由 AI 自稱完成而無證據的情況。
